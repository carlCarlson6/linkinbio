## Evidence and Mapping

### 1. Plaintext Clerk secrets remain on disk, including keyless instance material
- **Severity:** High
- **Affected area:** `.env`, `.clerk/.tmp/keyless.json`, `.clerk/.tmp/README.md`
- **Risk:** Plaintext credentials in the working tree can leak through accidental sharing, backups, logs, or mistaken commits.
- **Tracking:** Covered by `SEC-002`.

### 2. Authorization is only signed-in gating, with no server-side privilege boundary
- **Severity:** Medium
- **Affected area:** `src/routes/__root.tsx`, `src/routes/dashboard.tsx`
- **Risk:** Future sensitive features would inherit coarse `any signed-in user` access control.
- **Tracking:** Covered by `SEC-003`.

### 3. Residual supply-chain exposure from continued nightly usage and stale lockfile metadata
- **Severity:** Low
- **Affected area:** `package.json`, `package-lock.json`
- **Risk:** The original drift risk is reduced, but the project still depends on a nightly/pre-release channel and stale metadata can confuse future reviews.
- **Tracking:** Related to `SEC-001`.

### 4. Startup env validation is defined but not enforced at app startup
- **Severity:** Low
- **Affected area:** `src/env.ts`
- **Evidence:** `src/env.ts` defines required Clerk keys, but no imports of `env.ts` were found under `src/` during this review.
- **Risk:** Missing configuration may surface only at runtime instead of being validated early during app startup.
- **Tracking:** Added as `SEC-004`.
